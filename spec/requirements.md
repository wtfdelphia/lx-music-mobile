# 需求事实

本文记录 lx-music-mobile 的**长期**需求边界与业务约束。单次变更的需求写在 `openspec/changes/<name>/proposal.md`，归档后其中的长期结论回写到本文。

## 产品定位

基于 React Native 的音乐播放器移动客户端。核心特征：应用**自身不提供音频数据源**，在线播放链接由用户配置的「自定义源」脚本返回。项目定位为技术可行性探索，非商业发行（协议约束见 `README.md` 项目协议章）。

设计取向明确不以新手友好为目标：默认设置与 UI 操作偏向可控性而非引导性。

## 平台范围

| 平台 | 状态 | 约束 |
|---|---|---|
| Android 5+ | 正式支持 | 主干能力基线，任何改动不得回退 |
| iOS | 适配已归档（2026-09-09，单设备验证通过，多设备覆盖为观察项），2026-09-10 并入 `main` | **不上架 App Store**，通过未签名 IPA + AltStore/SideStore 侧载分发 |
| HarmonyOS NEXT | 无支持计划 | — |

iOS 分发路径决定了两条硬约束：免费 Apple ID 签名有效期 7 天、同时最多 3 个应用；因此不得依赖 App Store 专属能力（IAP、TestFlight 分发假设）。

## 核心能力边界

### 音频来源

- 在线音频链接**只能**来自用户配置的自定义源脚本返回值，项目本身不解析、不托管、不校验音频合法性与准确性
- 音源元数据（歌曲名、歌手、专辑、榜单、歌单、搜索结果）从各平台公开接口拉取，等价于未登录态
- 内置音源适配层位于 `src/utils/musicSdk/`，覆盖 kw / kg / tx / wy / mg / bd / xm
- 自定义源脚本必须在沙箱内执行，不得获得宿主 JS 上下文的完整能力

### 自定义源沙箱

- Android 与 iOS 共用注入脚本 `assets/script/user-api-preload.js`；改动同时影响双端
- 沙箱须隔离脚本对宿主的访问面，只暴露约定的通信通道
- 脚本导入支持 `.lxmc` 文件与深链两条入口
- 第三方社区脚本原文入库于 `test/scripts-regression/candidates/` 仅用于回归断言，不受本项目风格规则治理

### 播放

- 前台播放、后台续播、锁屏与通知栏控制、播放列表机制（机制说明见上游文档）
- 播放引擎依赖 `react-native-track-player` 的 fork commit，行为以实测为准而非上游文档
- 播放失败需有降级路径（换源 / 提示），不得静默卡死

### 数据与同步

- 本地数据（我的列表、设置、缓存）来自用户设备，项目不对其合法性负责
- 自 v1.0.0 起支持连接独立部署的数据同步服务（lx-music-sync-server），协议实现在 `src/plugins/sync/`
- 同步协议变更必须保持双向兼容性：旧客户端连新服务、新客户端连旧服务

### 加密

- 加密能力用于音源接口签名与同步握手
- iOS 侧加密核心由 Rust 实现（`rust/lxcore/lxcore-crypto`，C ABI staticlib），Android 侧为 Java 实现
- **两端必须在字节级对齐**，唯一权威是黄金基准 `test/crypto-golden-vectors.json`；出现不一致时修实现，不改基准

### 版权与数据留存

- 使用过程中产生的版权数据不归本项目所有；协议要求使用者在 24 小时内清除
- 应用内不得内置或分发版权音频、封面等资源

## 质量要求

| 维度 | 要求 |
|---|---|
| 双端一致性 | Android 已有行为在 iOS 适配期间不得回退；共用代码改动需评估双端影响 |
| 加密正确性 | 黄金基准全量通过，宿主与 iOS 目标交叉编译均验证 |
| 构建可重复 | 开发机无需 macOS，iOS 构建验证全部由 GitHub Actions macOS Runner 完成 |
| 验证真实性 | 门禁必须能真实通过；已知红项须显式登记，不得伪装为生效门禁（现状见 `AGENTS.md` 验证矩阵） |
| 无凭据入库 | token、Cookie、账号密码、签名证书、keystore 不得进入仓库 |

## 明确的非目标

- 不上架 App Store，不实现内购与订阅
- 不提供、不代理、不缓存分发受版权保护的音频数据
- 不追求新手友好的默认配置
- 不支持 HarmonyOS NEXT
- 不引入 Android 行为变更（iOS 适配已并入 `main`，双端共用代码改动需评估双端影响）
- 不接受商业合作与捐赠
