## 方法与边界

本文只使用三类公开材料：

1. `wesley666/LynMusic` 仓库的 README 与 `doc/` 目录截图（截图文字经

## 产品形态说明

上游存在两套产品，公开描述需分开对待：

| 形态 | 技术 | 状态 |
|---|---|---|
| 开源版 | Kotlin Multiplatform，Android / iOS / 桌面 / TV / 车机 | 免费，GPL-3.0-or-later |
| App Store 商业版 | Swift 重写，iPhone / iPad / Mac | 上架销售，独立代码库 |

公众号文章原话：「LynMusic for App Store 是一个独立开发和发布的
商业化产品，和开源版 LynMusic 不是同一套代码」。仓库 `doc/` 的手机
截图经 Exif 确认来自 Android 设备。以下功能清单对两个形态合并标注，
差异处单独说明。

## 管理逻辑流程图（公开材料可还原的部分）

```
┌─────────────── 来源层 ───────────────────────────────────┐
│ 本地文件夹 │ SMB │ WebDAV │ Navidrome │ Subsonic │ Emby │
│ 飞牛音乐 │ 局域网 WiFi 传歌（商业版，导入到设备）        │
└────────────────────────┬──────────────────────────────────┘
                         ▼ 接入 / 导入
┌─────────────── 索引层 ───────────────────────────────────┐
│ 曲库统计：歌曲数 · 专辑数 · 艺人数（主界面常驻显示）      │
│ 浏览维度：歌曲 / 专辑 / 艺人 /（文件夹，商业版）          │
│ 全局搜索：歌曲、艺人、专辑                                │
└────────────────────────┬──────────────────────────────────┘
           ┌─────────────┼─────────────┐
           ▼             ▼             ▼
┌──── 组织层 ────┐ ┌─ 元数据治理 ─┐ ┌─ 播放消费 ──────────┐
│ 喜欢（一键）    │ │ 音乐标签      │ │ 每日推荐            │
│ 歌单           │ │（仅本地来源） │ │ 最近播放歌曲 / 专辑 │
│ 文本导入歌单    │ │ 歌词管理      │ │ 音质按网络类型分设  │
│               │ │（搜索/粘贴）  │ │ 播放缓存 / 空间管理 │
└───────────────┘ └──────────────┘ └─────────────────────┘
```

### 可观察的管理行为

1. 曲库统计（歌曲 / 专辑 / 艺人计数）常驻主界面顶部，是库状态的
   第一入口
2. 标签编辑权限与来源类型绑定：编辑器明确「仅显示本地文件夹来源」，
   远程来源曲目不在编辑范围内
3. 歌词与标签是两套独立管理面：歌词在设置里有自己的分组（API、
   搜索源、播放缓存），标签有侧边栏级入口
4. 音质设置按网络环境拆分：WiFi 和移动网络各自独立选择
   （原始 / 320 / 192 / 128）
5. 推荐页聚合三种消费入口：每日推荐、最近播放歌曲、最近播放专辑
6. 缓存治理有专门的空间管理入口（查看并清理）

## 公开材料无法回答的问题

以下问题只能读源码才能回答，本文不做推测：

- 扫描与索引的实现（增量策略、元数据读取、并发模型）
- 来源凭据的存储方式
- 曲库数据是否跨设备同步（公众号文章未提及）
- 「根据你的口味生成」推荐的具体算法
- 各来源协议的字段映射与错误处理
- 删除、移除曲目的交互定义（所有截图与文章均未出现删除类操作）

最后一项值得单独说明：公开材料里**完全看不到曲目删除或从曲库移除
的入口**，标签编辑器也只有编辑没有删除。这可能是截图覆盖不全，
也可能是产品确实把删除做得很隐蔽。这是公开材料的盲区，不能作为
「对方没有此功能」的依据。

## 与 add-ios-local-library 的功能级对照

只比功能项，不比实现。参照基线规则见 design.md §1.3。

### 两边都有

本地文件夹、Navidrome / Subsonic / Emby、三视图浏览、搜索、喜欢、
歌单、文本导入、歌词搜索、每日推荐（LX 已砍，编号留档）。

### 上游有、本设计没有

| 功能项 | 说明 |
|---|---|
| 文件夹分类浏览 | 对应本设计已延后的「子目录浏览」；商业版描述证实这是真实功能项 |
| 音乐标签独立入口 | 本设计的标签信息在单曲菜单级，只读 |
| 标签在线搜索 / 刷新 | 从在线元数据回填标签，本设计非目标（iOS 无写入能力） |
| 音质按网络类型分设 | 本设计只有全局蜂窝开关 + 单一音质项 |
| 局域网传歌 | 导入通道，本设计无 |
| 最近播放歌曲 / 专辑 | 播放计数的消费面；本设计有 play_count 字段但无展示 |
| 空间管理分组 | 本设计有「清理封面缓存」按钮，无独立分组 |
| 歌词粘贴 | 本设计无手动粘贴歌词 |
| SMB / WebDAV / 飞牛 | 已计划 P4 |

### 本设计有、上游公开材料未见

已下载曲目自动关联（F17）、定位符重签稳定设计、删除保护与扫描报告。
这些属于 LX 自有需求（design §1.3 的「LX 自有」类），不受净室参照
约束。
